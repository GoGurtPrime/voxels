# Work Item 18 — Packaging, Distribution & Platform Services

**Phase:** F — Production Hardening · **Prerequisites:** 17

---

## 1. Problem Statement

There is no way to give this game to anyone. No install target, no distributable layout, no versioning, no first-run experience, no player-facing documentation, and no platform-services integration. Everything so far has assumed a developer with a configured build tree.

## 2. Objective

Produce a self-contained, redistributable build a non-developer can unzip and play, with a proper first-run experience, and integrate optional platform services behind a feature flag.

## 3. Scope

**In scope:** CMake install/package targets, runtime dependency staging, versioning, first-run experience, player documentation, optional Steam integration, release checklist.

**Out of scope:** store page assets, certification submissions, console ports.

## 4. Implementation Tasks

1. **Install & package targets:** `cmake --install` and CPack producing per-platform archives (Windows ZIP, Linux tar.gz/AppImage, macOS .app bundle + DMG). Distributable layout:
   ```
   VoxelsGame/
     voxels_app(.exe)
     SDL2.dll / libSDL2.so / bundled dylib
     assets/packs/core.vpk
     assets/shaders/           (loose so the operator can tweak)
     README.txt
     LICENSE.txt / THIRD_PARTY_LICENSES.txt
   ```
   The editor ships separately as an internal tool, not in the player package.
2. **Runtime dependency staging:** every non-system shared library is copied into the package; verify with `dumpbin /dependents`, `ldd`, and `otool -L` that nothing resolves outside the package or the OS. On a clean VM with no dev tools installed, the package must run.
3. **Versioning:** a single source of truth (CMake project version) propagated into the executable, the window title, the main-menu corner, the log banner, save-file `engineVersion`, and pack compatibility metadata. Embed the git short SHA and build timestamp.
4. **First-run experience:** with no user data present — create the user directory tree, write default settings, show a brief controls/keybinds card on first launch (dismissible, re-openable from the pause menu), and land the player on the main menu with an obvious path to creating a world.
5. **Player documentation:** `README.txt` in the package covering controls, where saves live per OS, how to report a bug (with the log path), system requirements, and known limitations. Rewrite the repository `README.md` for developers: honest project status, build instructions per platform, the work item process, and links to [ARCHITECTURE.md](../ARCHITECTURE.md) / [DIAGRAMS.md](../DIAGRAMS.md) / [AGENT_RULES.md](../AGENT_RULES.md).
6. **Third-party licence compliance:** aggregate licences for SDL2, GLM, Dear ImGui, Asio, stb, dr_libs, glad, Catch2, and any fonts/art into `THIRD_PARTY_LICENSES.txt`, generated by the build so it cannot go stale.
7. **Optional Steam integration** behind `VOXELS_ENABLE_STEAM` (default `OFF`, and the build must be fully functional with it off):
   * A thin `IPlatformServices` interface with a `NullPlatformServices` default and a `SteamPlatformServices` implementation.
   * Initialize/shutdown the Steam API, overlay support, rich presence, a small achievement set (first block broken, first world created, first cave entered, first structure built), and cloud-save hooks against the existing save paths.
   * The SDK is not vendored; CMake looks for it at a configured path and cleanly disables the feature (with a message) when absent.
8. **Release checklist** committed as `docs/RELEASE_CHECKLIST.md`: version bumped, changelog updated, CI green on all platforms, sanitizer job green, soak test passed, packages built and smoke-tested on clean VMs, `ASSET_REQUESTS.md` reviewed for shipping placeholders, licences current.
9. **Clean-machine verification:** actually install and run each package on a machine/VM without developer tooling, and report the result. This is the acceptance test that matters.

## 5. Acceptance Criteria

* A produced archive, extracted on a clean machine with no compilers, SDKs, or SDL2 installed, launches and plays.
* The version string is consistent across window title, menu, log, and save metadata.
* First run creates the user directory, writes defaults, shows the controls card, and reaches gameplay without an error.
* `VOXELS_ENABLE_STEAM=OFF` builds and runs identically to today; `ON` (with the SDK present) initializes Steam, shows the overlay, and unlocks a test achievement.
* `THIRD_PARTY_LICENSES.txt` covers every bundled dependency.

## 6. Automated Tests

`tests/test_packaging.cpp` plus CI scripting:
* `Version.IsConsistentAcrossExecutableLogAndSaveMetadata`.
* `FirstRun.CreatesUserDirectoryTreeAndDefaultSettings`.
* `FirstRun.SecondLaunchDoesNotShowTheControlsCardAgain`.
* `PlatformServices.NullImplementationIsUsedWhenSteamDisabledAndAllCallsAreSafe`.
* `PlatformServices.AchievementTriggersAreFiredByRealGameplayEvents` — asserted through the game event path, not a direct call.
* `Package.LayoutContainsAllRequiredRuntimeFiles` — CI script asserting the staged package contents.
* `Licenses.GeneratedFileCoversEveryDeclaredDependency`.

## 7. Anti-Shell Checks

- [ ] The package was actually built and launched on a clean environment, or the inability to do so is explicitly reported.
- [ ] Steam code paths are genuinely optional — the default build has zero Steam dependency.
- [ ] Achievements are triggered by real gameplay, not stub calls.

## 8. Assets & Human Actions

* **Steam SDK (operator):** download the Steamworks SDK, extract it, and provide the path via `-DSTEAM_SDK_ROOT=<path>`. Provide the App ID. Not required for the default build.
* **Store/branding art (operator):** icon (`.ico`/`.icns`, 256×256), capsule/header art, and the final game title if it differs from the working name.
* **Clean test machine (operator):** a VM or second machine without developer tooling to validate the package.
* Record all of these in [ASSET_REQUESTS.md](../ASSET_REQUESTS.md).

## 9. Verification

Build, test, produce packages for the host platform, install on a clean environment, launch, play for several minutes, and report the complete result — including the exact archive name, size, and anything that did not work.
